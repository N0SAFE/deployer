## Core terms

- **ORPC**: Contract-first, type-safe API system used across API and web.
- **Contract**: Shared procedure definition in `packages/contracts/api`.
- **Declarative Routing**: Generated, typed route helpers based on `page.info.ts` metadata.
- **Domain hooks**: Web-layer hooks grouping fetch/cache logic by feature domain.
- **Docker-first development**: Preferred local execution model through compose stacks.
- **Catalog dependencies**: Workspace-level version catalog used for dependency consistency.

## Platform terms

- **Cluster**: A group of 1+ nodes running the deployer platform, sharing a PostgreSQL database.
- **Node**: A single VPS/server participating in the Docker Swarm cluster.
- **Manager node**: A Swarm control-plane node that owns orchestration state and scheduling decisions.
- **Worker node**: A Swarm execution node that runs scheduled service replicas/tasks.
- **Organization**: A tenant boundary within a cluster; owns projects and has configurable instance allocation.
- **Project**: A logical grouping of related services (e.g. frontend + backend + worker). Owns its own Docker network.
- **Service**: A single deployable unit within a project (four types: web, worker, cron, one-shot).
- **Mesh**: ORPC EventIterator over HTTP/SSE gossip-ring network connecting all API nodes for event distribution.
- **Load Balancer (LB)**: Optional advanced redirect/token routing component; not required for the default Traefik + Swarm ingress path.
- **Preview environment**: Auto-created per PR/branch with deterministic subdomains, scale-to-zero, and LRU eviction.
- **Config-as-code**: `deployer.yaml` file in user repos that bidirectionally syncs with the dashboard via PRs.
- **Cascade deploy**: When a dependency service redeploys, dependent services auto-redeploy (configurable per edge).
- **One-shot task**: A container that runs once to completion (e.g. database migrations before deploy).
- **Scale-to-zero**: Service containers stop after inactivity; wake-on-first-request with a loading screen.

## Architecture terms

- **Service-Adapter pattern**: API pattern where controllers orchestrate, services hold business logic, and adapters map entities to contract shapes.
- **Internal package**: Shared workspace package imported as `@repo/*`.
- **Workspace graph**: Turbo task dependency graph across apps/packages.
- **Boundary rule**: Keep contracts in shared packages, implementation in API, and data orchestration in web hooks.
- **Auth guard chain**: Request protection flow combining authentication and role/permission checks.

## Operational terms

- **Prod-like**: Environment approximating production constraints locally.
- **Quality gate**: Repository-wide `bun run check` validation pipeline.
- **Canonical docs**: Maintained documentation under the docs app content hierarchy.
- **Project isolation**: Compose namespace strategy (`COMPOSE_PROJECT_NAME`) to avoid container/network collisions.
- **Migration lifecycle**: Schema update, migration generation, migration application, and optional seeding.
