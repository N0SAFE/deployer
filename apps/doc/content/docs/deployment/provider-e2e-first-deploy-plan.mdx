## Executive summary

The provider stack is **asymmetric**: the GitHub (code) surface has 27 fixture sites proving shapes but **zero writers** for the real `github_repository_configs` mapping; the Cloudflare (DNS) surface talks to real APIs (SDK, tunnels, zones/records) but has **six gaps** that break creates and records; the ingress **double-publishes** the same Host (two YAML files, parallel, no dedupe) and has **zero TLS scaffolding**; the web has **24 type errors** (22 mechanical `.body` drift in one file + 2 config-package typing) and dashboards are mostly real with 2 skeleton spots; the webhook auth guard can silently **downgrade to no-auth** (missing/missing-DB secret), uses a single shared secret, in-memory idempotency, HMAC over re-serialized JSON; retry is a **documented no-op** (enqueue TODO) and Redis is **absent** (Bull fails silently, swallowed); hygiene is 6/6 verified.

### D-1 — Load balancer app REMOVED entirely (architectural decision)
The standalone `apps/load-balancer` is **deleted** — it is not necessary:

- **Deployment access** is handled by **Traefik redirect or the direct-proxy
  supervisor** depending on setup (Traefik healthy = Traefik route; Traefik
  down = DirectProxySupervisor takes over, then self-closes).
- **Direct app access** needs no LB: Traefik is small (single-node self-hosted);
  the platform never needed an external balancer in front of it.

### D-2 — `appInstance` removed from the global ORPC context (antipattern fix)
`context.appInstance` was declared OPTIONAL in `ORPCGlobalContext` + populated by
a root `AppInstancePlugin`, forcing every consumer to null-check — an
antipattern. Per the same model as `requireAuth()`:

- New typed middleware `requireAppInstance(appInstances)` in
  `modules/platform/orpc/middlewares.ts`: resolves `X-App-Instance-Token`,
  throws `UNAUTHORIZED` when missing/invalid, and **narrows the context so
  `appInstance` is guaranteed present** after it runs.
- `heartbeat()` in `platform.controller.ts` uses `.use(requireAppInstance(…))`;
  the `context.appInstance === undefined` check is **deleted**.
- `ORPCGlobalContext` no longer declares `appInstance` (nothing optional leaks
  into the global context); `AppInstancePlugin` deleted.
- Initial context stays `{ request, auth }` — plugins array only carries
  `SmartCoercionPlugin` + `AuthPlugin`, both typed over the merged context.

### D-4 — First-boot ingress reachability (web.deployer.localhost during setup)
**User report**: on FIRST boot (setup phase, no database yet) `web.deployer.localhost`
was unreachable even though the Traefik supervisor had converged.

**Root cause**: the Traefik dynamic config was written ONLY in
`OrchestratorService.startMainApp()` — i.e. AFTER setup completes (the DB exists
condition). On first boot the pipeline goes `runDbResolver → startSetupWizard`
and main-app is never reached during setup, so the file-provider watched
directory was EMPTY → Traefik had no `Host()` rules → both
`api.deployer.localhost` and `web.deployer.localhost` returned nothing. The
supervisor (process) converging was correct — the CONFIG (core module) just
never existed yet.

**Fix** (2 parts):
1. **Boot-time publish** — `OrchestratorService.onApplicationBootstrap` now calls
   `ingressConfig.writePlatformConfigs()` right after the DB resolver (Step 1a),
   so api + web routes exist from the moment the pipeline starts, including the
   setup-wizard phase. `startMainApp()` still rewrites (idempotent) with the
   now-available DB domain routes.
2. **DB-resilient domain family** — `resolveDomainRoutes()` now catches the
   missing-global-DB failure (first boot has no `deployments` table) and returns
   `[]`; the domain file is removed and api/web are still written. Previously
   the `Promise.all` in `writePlatformConfigs()` aborted everything when the
   DB query threw.

Backends at boot are explicit compose targets (`DEPLOYER_API_TARGET=api-dev`,
`DEPLOYER_WEB_TARGET=web-dev`), both attached to `deployer-platform`, so
`api.deployer.localhost → api-dev:3005` (gateway hosts the setup-wizard
sub-app routes) and `web.deployer.localhost → web-dev:3000` work during setup.

Regression test added: `traefik-platform-config.service.spec` — "publishes api +
web during FIRST BOOT when the global DB is absent (setup phase)" (routesSource
rejects → api.yml + web.yml exist, domain.yml removed). Config suites 7/7.
