# Startup v2 — Implementation Plan

## Overview

Replace the entire v1 startup system (`CoreStartupService`, `StartupOrchestratorService`, all per-module `*StartupService`, `FeatureModuleLoader`, `FeatureModuleFactory`) with the v2 **Sub-App Trigger Chain** pattern.

**Delete**: 29 old files
**Modify**: 3 existing files  
**Create**: ~30 new files
**Keep**: 28 existing files (v2 foundation)

---

## Implementation Order (Topological)

### Pre-phase: Move MeshVersionService
Must happen first — it's imported by v2 code but lives in the v1 directory.

| Step | Action | Files |
|------|--------|-------|
| P.1 | Move `MeshVersionService` to `core/modules/mesh/version/` | MOVE from `core/modules/startup/mesh-version.service.ts` to `core/modules/mesh/version/mesh-version.service.ts` |
| P.2 | Update imports in `initialization.module.ts` | Change `../startup/mesh-version.service` → `../mesh/version/mesh-version.service` |
| P.3 | Update imports in `remote-initialization.service.ts` | Same import path change |

### Phase 0: Foundation Layer
No dependencies on any other new code.

| Step | File | Purpose |
|------|------|---------|
| 0.1 | `core/modules/triggers/trigger.ts` | `Trigger&lt;T&gt;` class with `fire()`, `waitFor()`, `resolved`, `value` |
| 0.2 | `core/modules/triggers/trigger-registry.ts` | `TriggerRegistry` + all payload type interfaces |
| 0.3 | `core/modules/triggers/triggers.module.ts` | `@Global()` module exporting `TriggerRegistry` |
| 0.4 | `core/modules/sub-app-runner/sub-app.interface.ts` | `SubApp&lt;T&gt;`, `SubAppContext&lt;T&gt;` interfaces |
| 0.5 | `core/modules/sub-app-runner/tokens.ts` | `SUB_APP_CONTEXT` symbol |
| 0.6 | `core/modules/sub-app-runner/sub-app-context.module.ts` | `SubAppContextModule.forRoot()` dynamic module |
