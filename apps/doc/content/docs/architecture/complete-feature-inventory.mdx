## 7b. Docker Control Panel (independent, node-scoped)

> **Scope**: Every node has a full Docker control panel accessible independently of projects and services. Users with the right permissions can manage **any container** on any node they have access to — not just deployer-managed ones. Think Portainer-equivalent, built directly into the platform.
>
> **Transport**: all Docker actions go through the node's API agent via the existing ORPC mesh. The web sends `docker.*` ORPC calls to the target node's agent; the agent calls `dockerode` locally.

### 7b.1 Container management

| Feature | Status | Notes |
|---------|--------|-------|
| List all containers on a node (running + stopped, managed + unmanaged) | 🔴 | `dockerode.listContainers({ all: true })` — no ORPC endpoint |
| Filter containers by label, name, status, project, service | 🔴 | Client-side filter on full list |
| Container detail view (image, command, ports, volumes, env, network, labels) | 🔴 | `dockerode.getContainer(id).inspect()` |
| Start / stop / restart / pause / unpause / kill — individual container | 🔴 | All available in dockerode, not exposed |
| Remove container (with optional volume cleanup) | 🔴 | `dockerode.getContainer(id).remove({ v: true })` |
| Rename container | 🔴 | `dockerode.getContainer(id).rename()` |
| **Interactive terminal into any container** (`docker exec` attach via WebSocket/xterm.js) | 🔴 | `dockerService.exec()` exists, no ORPC stream endpoint or web UI |

## 14b. Infrastructure & Runtime Monitoring

> **Architecture**: each node runs a lightweight metrics agent (sidecar) that collects system and Docker stats, writes to a time-series store (or streams directly over ORPC SSE), and exposes them to the platform API. The web dashboard consumes these via ORPC hooks + react query, rendering live charts.
>
> **Granularity levels** (all supported independently):
> - Per **server/node** (host-level)
> - Per **project** (aggregated across all services in project, across all nodes)
> - Per **service** (all replicas of a single service)
> - Per **replica / container** (individual container on a specific node)
>
> **Metric collection strategy**: `dockerode.getContainer(id).stats({ stream: true })` for per-container Docker stats + **`systeminformation`** npm package for all host-level metrics (CPU, memory, disk, GPU, network, processes).

### 14b.1 Host / Node metrics (per server)

| Metric | Granularity | Notes |
|--------|-------------|-------|
| CPU usage % (per core + aggregate) | real-time + history | `systeminformation.currentLoad()` — 1 s resolution |
| CPU load averages (1m / 5m / 15m) | real-time | `systeminformation.currentLoad().avgLoad` |
| CPU temperature (per core, if available) | real-time | `systeminformation.cpuTemperature()` |
| CPU model, core count, thread count, base/boost clock | static | `systeminformation.cpu()` — read on agent start |
| Memory: total, used, free, cached, buffers | real-time + history | `systeminformation.mem()` |
| Memory swap: total, used, free | real-time | `systeminformation.mem()` — swap fields |

### 19d. Global UX patterns

| Pattern | Implementation |
|---------|---------------|
| **Command palette** | `Cmd+K` → shadcn `<CommandDialog>` — fuzzy-search across projects, services, deployments, routes, actions |
| **Toast notifications** | `sonner` — bottom-right; `success` (emerald), `error` (rose), `loading` (spinner), `info` (blue) |

| **Status badge** | shadcn `<Badge variant="outline">` with colored dot + label; color from token table above |
| **Live indicator** | Pulsing dot (animate-ping CSS) on "running" status; stops when service stops |
| **Skeleton loading** | shadcn `<Skeleton>` matching exact layout of loaded content — prevents layout shift |
| **Empty states** | Centered icon + title + description + primary CTA button; uses `lucide` icon, muted palette |
| **Confirmation dialogs** | shadcn `<AlertDialog>` — destructive actions (delete, prune, remove) always require confirmation |
| **Inline help** | shadcn `<Tooltip>` on icon buttons; shadcn `<HoverCard>` on complex terms |
| **Responsive** | Sidebar → bottom-sheet on mobile (`vaul`); tables → cards on `<768px`; side panels → full-screen bottom sheet |
| **Keyboard nav** | All dialogs / dropdowns trap focus; Esc closes; Tab cycles; Arrow keys navigate lists |
| **URL state** | Filter values, active tabs, pagination stored in URL via `nuqs` — shareable and back-button safe |

## 20c. Service Dependency Graph (React Flow)

> **Library**: [`@xyflow/react`](https://reactflow.dev) (React Flow v12) — chosen for its first-class TypeScript support, custom node/edge components, minimap, zoom/pan, and layouting compatibility with `dagre` or `elkjs`.
>
> **Scope**: the graph operates at **project level** — shows all services in a project, their declared dependencies, and live runtime state. It is also accessible in a cross-project view for services that depend on services in other projects.

### 20c.1 Node types (React Flow custom nodes)

| Node type | Visual description | Data shown |
|-----------|-------------------|------------|
| `ServiceNode` | Rounded card — service name, type badge (web/worker/cron/db), status indicator ring (green/yellow/red) | Name, type, status, last deploy |
| `ServiceNode` (expanded) | Click to expand inline: CPU%, memory%, replica count, health check result, deploy button | Live metrics |
| `ReplicaNode` | Smaller card attached below `ServiceNode` when replica toggle is ON — one per running replica | Container ID (short), node it runs on, CPU%, memory%, health |
| `ExternalNode` | Hexagon — represents external dependency (e.g. a GitHub repo, an external DB URL, a third-party API) | Name, type, URL (masked) |
| `RegistryNode` | Container icon — represents a registry endpoint | Registry name, image tag |
| `ComposeStackNode` | Stack of rectangles icon — represents a Compose stack | Stack name, service count, status |

### 20c.2 Edge types

| Edge type | Meaning | Visual |
|-----------|---------|--------|
| `DependsOnEdge` | Service A must start before service B | Solid arrow, neutral color |
| `SoftDependsOnEdge` | Service A prefers but doesn't require service B | Dashed arrow |
| `HealthGateEdge` | Service A only starts when service B is healthy | Solid arrow with health icon |
| `NetworkEdge` (optional) | Two services share a Docker network (live, from Docker inspect) | Thin dotted line, grey |
| `ImagePushEdge` | Build output image pushed to registry node | Dashed arrow to RegistryNode |
| `ImagePullEdge` | Replica pulls from registry | Dotted arrow from RegistryNode to ReplicaNode |

### 20c.3 Graph controls & interactions

| Control | Behaviour |
|---------|-----------|
| **Replica toggle** (toolbar button) | Expand all `ServiceNode`s to show individual `ReplicaNode` children; re-layout with `dagre` to accommodate new nodes |
| **Live stats toggle** | Show/hide the live CPU%/memory% overlay on each node; subscribes to `metrics.live` SSE stream |
| **Health filter** | Hide healthy nodes — show only degraded/down services and their upstream dependents |
| **Deployment highlight** | When a deployment is in progress, animate that service's node and its downstream dependents |
| **Click node** | Side panel slides in: service detail, deploy controls, recent logs, metric mini-charts |
| **Right-click node** | Context menu: deploy, rollback, stop, view logs, open terminal |
| **Drag to reorder** | User can drag nodes — layout hint saved per-project (custom position override stored in DB) |
| **Auto-layout** | Button to reset to `dagre` top-bottom layout or `elkjs` layered layout (selectable) |
| **Zoom to fit** | Fit all nodes in viewport |
| **Minimap** | React Flow built-in minimap in bottom-right corner |
| **Edge labels** | Toggle edge labels: show dependency type or network name |
| **Export** | Export graph as SVG or PNG (React Flow `toSvg()` / `toPng()`) |

### 20c.4 Layout strategy

| Layout engine | When used |
|---------------|----------|
| `dagre` (npm `@dagrejs/dagre`) | Default — fast, deterministic top-to-bottom DAG layout; good for most projects |
| `elkjs` (npm `elkjs`) | Opt-in for large projects (>20 services) — better edge routing, layers algorithm |
| Manual (stored positions) | When user has dragged nodes — overrides auto-layout; reset button clears stored positions |

### 20c.5 Data sources

| Data | ORPC endpoint | Update frequency |
|------|---------------|------------------|
| Service list + dependency declarations | `project.serviceGraph` | On page load + on deploy event |
| Service runtime status | `service.status` SSE per project | Real-time (push) |
| Replica list (when replica toggle on) | `node.docker.containers.list` filtered by project label | Live polling 5 s |
| Live metrics per node (CPU%, mem%) | `metrics.live` SSE | 2 s cadence |
| Health check last result | `healthCheck.latest` per service | Live push on state change |
| Active deployment state | `deployment.active` SSE | Real-time (push) |

### 20c.6 Cross-project graph view

| Feature | Notes |
|---------|-------|
| Global service graph (`/admin/graph`) | All projects and services on one canvas — React Flow handles large graphs with virtualization |
| Project grouping (React Flow sub-flows / groups) | Each project is a group node; expand to see services inside |
| Cross-project dependency edges | Shown as dashed edges between group nodes or service nodes directly |
| Provider nodes (registries, DNS, Traefik) | Infrastructure nodes shown at the edges of the graph |
