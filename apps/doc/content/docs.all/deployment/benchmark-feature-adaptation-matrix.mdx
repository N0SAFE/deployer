## Goal

Capture high-value patterns seen in mature platforms (Dokploy, Coolify, Dockhand) and map them into **Deployer-native** architecture so we improve capability without fragmenting design.

This page focuses on adaptation, not copy.

---

## Design principles for adaptation

1. **Contract-first and typed**: every adapted feature must fit ORPC/contracts + schema-first model.
2. **Policy-driven behavior**: no hardcoded product logic where policy/template can express behavior.
3. **Single canonical execution checklist**: every adaptation maps to `Txxx` tasks in migration breakdown.
4. **Connected documentation**: each feature links to architecture, execution, and operator runbook docs.

---

## Adaptation matrix

| Benchmark pattern | Observed value | Deployer adaptation | Task mapping |
|---|---|---|---|
| Change-scoped Git deploys (directory/path awareness) | Avoids noisy redeploys in monorepos | Extend trigger rule engine with deterministic path-diff filters + policy preview | `T191`, `T229` |
| Rich role/permission surfaces | Enables least-privilege ops at scale | Expand custom role matrix for deploy/registry/backup/audit domains with environment scope | `T146`, `T230` |
| One-click service/catalog templates | Fast onboarding and consistency | Signed internal template catalog (`Template Packs`) with compatibility metadata and risk labels | `T085`, `T227` |
| Secure remote host connectivity modes | Better usability across LAN/NAT/VPS | Standardize remote control-plane connectivity profiles (`direct`, `edge`) with explicit trust diagnostics | `T125`, `T228` |
| Security-aware auto-update workflows | Safe updates with vulnerability checks | Unify Trust Gate + rollout policy so update paths can block on signature/provenance/security criteria | `T222`, `T231` |
| Async operations with script-friendly sync mode | Better UX + automation interoperability | Add typed async job contract and optional synchronous response mode for long operations | `T232` |

## Connectivity plan (docs)

For each adapted feature, keep this doc chain intact:

1. **Architecture intent**: `/docs/architecture/platform-product-spec`
2. **Feature target placement**: `/docs/deployment/platform-feature-target`
3. **Execution task**: `/docs/deployment/migration-task-breakdown`
4. **Deep operator/implementation spec**: dedicated deployment doc

If one link is missing, the feature is considered under-documented.
