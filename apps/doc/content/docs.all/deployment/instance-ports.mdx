## Principle

No port is hardcoded in any source file, Dockerfile, or Compose file. Every port is:

1. **Declared once** in the root `.env` file (or `.env.local` override)
2. **Passed as a variable** to every Compose service that needs it
3. **Defaulted** inline with `${VAR:-default}` syntax so services start without a `.env` file in development

---

## Port reference — per node

| Service | Variable | Default | Exposed to host | Internal alias |
|---|---|---|---|---|
| NestJS API | `API_PORT` | `3005` | yes | `api-dev` / `api-prod` |
| Next.js Web | `WEB_PORT` / `NEXT_PUBLIC_APP_PORT` | `3000` | yes | `web-dev` |
| Custom LB app | `LB_PORT` | `3010` | yes | `lb-dev` |
| Traefik HTTP | `TRAEFIK_HTTP_PORT` | `80` | yes | `traefik` |
| Traefik HTTPS | `TRAEFIK_HTTPS_PORT` | `443` | yes | `traefik` |
| Traefik dashboard | `TRAEFIK_DASHBOARD_PORT` | `8080` | internal only | `traefik` |
| PostgreSQL | `DB_PORT` | `5432` | dev only | `api-db` |
| Redis | `REDIS_PORT` | `6379` | dev only | `api-redis` |
| Documentation site | `DOC_PORT` | `3001` | dev only | `doc-dev` |

## How Compose files share the values

All services read from the same `.env` at the Compose project root. Docker Compose automatically loads it.

```
deployer/v3/
├── .env                          ← single source of truth for ports
├── docker/compose/
│   ├── api/docker-compose.api.dev.yml
│   ├── web/docker-compose.web.dev.yml
│   ├── load-balancer/docker-compose.load-balancer.dev.yml
│   ├── traefik/docker-compose.traefik.dev.yml   (when added)
│   └── docker-compose.dev.yml    ← includes all of the above
```

### Example: how `API_PORT` flows through every file

```yaml
# .env
API_PORT=3005
LB_PORT=3010
WEB_PORT=3000

# docker/compose/api/docker-compose.api.dev.yml
services:
  api-dev:
    ports:
      - "${API_PORT:-3005}:${API_PORT:-3005}"
    environment:
      - API_PORT=${API_PORT:-3005}

# docker/compose/load-balancer/docker-compose.load-balancer.dev.yml
services:
  lb-dev:
    ports:
      - "${LB_PORT:-3010}:${LB_PORT:-3010}"
    environment:
      - LOAD_BALANCER_PORT=${LB_PORT:-3010}
      - API_URL=http://api-dev:${API_PORT:-3005}   # ← uses API_PORT here too

# docker/compose/web/docker-compose.web.dev.yml
services:
  web-dev:
    ports:
      - "${WEB_PORT:-3000}:${WEB_PORT:-3000}"
    environment:
      - NEXT_PUBLIC_APP_PORT=${WEB_PORT:-3000}
      - API_URL=http://api-dev:${API_PORT:-3005}
```

Changing `API_PORT=3007` in `.env` automatically updates the port binding, the API's own env, and the `API_URL` used by the LB and Web — all in one change.

## Multi-node mesh — per-node port overrides

In the 6-node dev mesh, each API node binds to a distinct port on the host. The shared services (PostgreSQL, Redis) are still single instances.

```yaml
# docker-compose.mesh-6.dev.yml

api-mesh-dev-1:
  ports:
    - "${MESH_API_PORT_1:-3301}:3301"
  environment:
    - API_PORT=3301

api-mesh-dev-2:
  ports:
    - "${MESH_API_PORT_2:-3302}:3302"
  environment:
    - API_PORT=3302

# ...through api-mesh-dev-6 on port 3306

web-mesh-dev:
  ports:
    - "${NEXT_PUBLIC_APP_PORT:-3000}:3000"
  environment:
    - API_URL=http://api-mesh-dev-1:3301   # web connects to node-1 by default
```

Variables like `MESH_API_PORT_1` through `MESH_API_PORT_6` allow overriding individual node ports without affecting the standard single-node dev setup.

## Traefik upstream configuration

Traefik must know the LB port and API port to route traffic correctly. These are passed via environment variables or a mounted config file generated at startup.

```yaml
# docker/compose/traefik/docker-compose.traefik.dev.yml  (planned)
services:
  traefik:
    ports:
      - "${TRAEFIK_HTTP_PORT:-80}:80"
      - "${TRAEFIK_HTTPS_PORT:-443}:443"
      - "${TRAEFIK_DASHBOARD_PORT:-8080}:8080"
    environment:
      # Used to generate the dynamic config pointing to the LB and API
      - LB_UPSTREAM_URL=http://lb-dev:${LB_PORT:-3010}
      - API_UPSTREAM_URL=http://api-dev:${API_PORT:-3005}
      - WEB_UPSTREAM_URL=http://web-dev:${WEB_PORT:-3000}
```

Traefik's dynamic config (written by the API via the HTTP provider or Docker labels) also uses these variables — never hardcoded IPs or ports.

## Production overrides

In production, the `.env` file is replaced by actual environment variables set in the server's shell or a secrets manager (Vault, 1Password, etc.). Compose files always fall back to the same defaults, so a partial env file still works.

```bash
# On a production server — set only what differs from defaults
export API_PORT=3005       # same as default, shown for clarity
export LB_PORT=3010
export TRAEFIK_HTTP_PORT=80
export TRAEFIK_HTTPS_PORT=443
# DB_PORT stays at default 5432 — no need to set it
```
