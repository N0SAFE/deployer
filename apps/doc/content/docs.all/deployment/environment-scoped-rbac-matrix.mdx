## Goal

Extend RBAC to enforce least privilege by both **domain** and **environment scope**, reducing over-privileged access for sensitive operations.

---

## Domains

- `deploy`
- `registry`
- `backup`
- `audit`

Each permission grant can be scoped to environment selectors such as `preview`, `staging`, `production`, or explicit environment IDs.

---

## Scope (v1)

### In scope

- Typed permission model with domain + action + environment scope
- Least-privilege preset roles (`operator`, `release-manager`, `auditor`, `backup-admin`)
- Effective permission explain endpoint for actor+resource+environment
- Deny-first conflict resolution

### Out of scope (v1)

- ABAC-style free-form policy language
- external IdP policy federation

## Permission model

```ts
type RbacDomain = "deploy" | "registry" | "backup" | "audit";

type EnvScope = {
  include: string[]; // e.g. ["preview", "staging"]
  exclude?: string[];
};

type PermissionGrant = {
  domain: RbacDomain;
  action: string;    // e.g. deploy.trigger, registry.push, backup.restore, audit.export
  scope: EnvScope;
  effect: "allow" | "deny";
};
```

---

## Resolution semantics

For request $r = (domain, action, env)$ with matching grant set $G$:

```latex
allow(r) = (\exists g \in G : g.effect = allow) \land \neg(\exists g \in G : g.effect = deny)
```

If no grant matches, default is deny.

---

## Preset role examples

- `operator`: deploy actions in `preview`/`staging`, no production deploy
- `release-manager`: deploy in all envs + controlled rollback actions
- `auditor`: read/export in `audit`, no mutation rights
- `backup-admin`: backup create/restore in designated env scopes only

- `rbac_scope_denied`

- `rbac_environment_not_allowed`
- `rbac_preset_conflict`
- `rbac_policy_invalid`

## Test strategy

### Unit

- environment include/exclude matching
- deny-overrides-allow precedence
- unknown action/domain handling

### Integration

- permission evaluation in deploy/registry/backup/audit endpoints
- effective-permission explain endpoint stability
- preset import and custom override behavior

### E2E

- operator can deploy in staging but denied in production
- auditor can export logs but cannot trigger deployment
- backup-admin restore blocked outside allowed env scope
