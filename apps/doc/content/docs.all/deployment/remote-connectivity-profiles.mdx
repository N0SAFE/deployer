## Goal

Standardize fleet node onboarding with explicit connectivity profiles so operators can reliably connect nodes across public VPS, private LAN, and NAT-restricted environments.

---

## Profiles

- `direct`: node is directly reachable by control-plane (stable URL/IP + inbound access)
- `edge`: node initiates outbound control tunnel/session to allocator/control-plane (for NAT/firewalled nodes)

---

## Scope (v1)

### In scope

- Typed connectivity profile model on node enrollment
- Profile-aware onboarding checks and diagnostics
- Trust diagnostics (identity/token/clock skew/replay guard health)
- Operator troubleshooting views for enrollment/connectivity failures

### Out of scope (v1)

- Multi-hop mesh relay auto-selection by geography
- Full dynamic tunnel broker marketplace integrations

---

## Typed model

```ts
type ConnectivityProfile = "direct" | "edge";

type NodeConnectivityConfig = {
  profile: ConnectivityProfile;
  advertisedUrl?: string; // required for direct
  edge: {
    heartbeatIntervalMs?: number;
    reconnectBackoffMs?: number;
    maxSessionAgeMs?: number;
  };
};

type ConnectivityDiagnostic = {
  status: "ok" | "degraded" | "failed";
  reasonCode: string;
  details?: Record<string, string | number | boolean>;
};
```

---

## Decision and readiness

Readiness for node admission is profile-aware:

```latex
admit = trustValid \land connectivityHealthy \land policyAllowed
```

Where `connectivityHealthy` is derived from profile-specific probes:

- `direct`: inbound reachability + control-plane handshake + latency budget
- `edge`: outbound session establishment + keepalive continuity + token freshness

---

## Diagnostics taxonomy

- `connectivity_direct_unreachable`
- `connectivity_direct_tls_invalid`
- `connectivity_edge_session_not_established`
- `connectivity_edge_keepalive_stale`
- `connectivity_trust_token_invalid`
- `connectivity_clock_skew_exceeded`
- `connectivity_profile_misconfigured`

---

## Operator UX expectations

- Connectivity profile selector during node onboarding
- Diagnostics panel with:
  - current profile,
  - handshake/session status,
  - last successful heartbeat,
  - reason code + remediation hints
- One-click test probe action before final admission

---

## Test strategy

### Unit

- profile config validation (`direct` requires URL; `edge` requires tunnel/session settings)
- reason-code mapping for failed probes

### Integration

- direct profile success/failure probes
- edge profile session establishment and stale keepalive behavior
- trust + connectivity combined admission gate

### E2E

- NAT-like node onboarding via edge profile succeeds
- misconfigured direct profile rejected with deterministic reason
- diagnostics endpoint returns stable contract in both profiles

- failure taxonomy is stable and test-covered
