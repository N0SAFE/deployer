## Summary

This document locks a strict delivery boundary:

1. **Phase 1** = complete Docker operator surface for the web app, independent from project/service/deployment coupling.
2. **Phase 2** = additive linkage back to deployments/projects/services for richer context.

If linkage data is unavailable, stale, or delayed, core Docker operations must still work.

---

## Phase boundary rules (non-negotiable)

1. Core Docker pages (`containers`, `images`, `networks`, `volumes`, `stacks`, `registry`, `events`, `logs`, `terminal`) must not require deployment-linked data to function.
2. Runtime truth for Phase 1 is Docker runtime + mesh/runtime streams.
3. Linked projections are allowed only behind explicit linked adapters/endpoints and must remain optional.
4. Phase 2 enrichment must degrade gracefully (no hard fail of core runtime operations).

Loading UX is now standardized across Docker list pages and detail modals:

- List pages now render explicit loading notices and table-row skeleton placeholders during initial runtime data fetch.

This reduces false-negative “empty” impressions during startup/reconnect and keeps transitional states consistent with the rest of v3 dashboard UX.

## Exact page functionality contract (Dockhand parity + v3 enhancement ideas)

This section is the exact functional target for Docker pages. “Dockhand parity” is the baseline. “Enhancements” are value-adds to implement after parity (or in parallel if low-risk).

### Containers page (`/dashboard/docker/containers`)

**Must support (Dockhand parity baseline):**

- Container list with search/filter/sort and environment scoping.
- Lifecycle actions: `start`, `stop`, `pause`, `unpause`, `restart`, `remove`.
- Bulk operations: batch update stream and bulk action feedback.
- Create/edit/rename flows for containers.
- Inspect views: full inspect payload, stats, top/processes.
- File browser operations: list/read/write/create/delete/rename/chmod/upload/download.
- Interactive shell/exec session (WebSocket terminal behavior equivalent).
- Logs access from container context (point-in-time + streaming).
- Maintenance actions: container prune and update-check workflows.

**Enhancement ideas (v3+):**

- Safe bulk planner (dry-run impact preview before destructive actions).
- Policy-based guardrails (protected labels/environments require elevated confirmation).
- Command history and reusable operation presets.

### Images page (`/dashboard/docker/images`)

**Must support (Dockhand parity baseline):**

- Image list grouped by repository/tag with search/filter/sort.
- Pull image with progress stream.
- Tag, remove, and prune (`dangling` and full prune variants).
- Image history/layers view.
- Export image artifact.
- Registry-linked actions (push/copy where supported).
- Security scan initiation and results surface.

**Enhancement ideas (v3+):**

- Digest pin recommendation and mutable-tag risk warnings.
- SBOM/attestation visibility per image.
- “Used by runtime” impact graph before prune/delete.

### Networks page (`/dashboard/docker/networks`)

**Must support (Dockhand parity baseline):**

- List/create/inspect/delete networks.
- Connect and disconnect containers to/from networks.
- Network prune workflows.

**Enhancement ideas (v3+):**

- Connectivity simulation (“what breaks if network X is removed?”).
- Network policy templates and reusable environment profiles.

### Volumes page (`/dashboard/docker/volumes`)

**Must support (Dockhand parity baseline):**

- List/create/inspect/delete volumes.
- Volume clone and export workflows.
- Volume browse and lock/release semantics for file browser sessions.
- Volume prune workflows.

**Enhancement ideas (v3+):**

- Snapshot/restore UX for operator recovery.
- Retention policy automation and orphaned-volume insights.

### Stacks page (`/dashboard/docker/stacks`)

**Must support (Dockhand parity baseline):**

- Stack list + source visibility.
- Stack lifecycle actions: `start`, `stop`, `restart`, `down`, `delete`.
- Compose/env workflows: read, edit raw env, validate env, compose retrieval/update.

- Git stack integration signals (deploy stream/status where applicable).

**Enhancement ideas (v3+):**

- Desired-vs-actual drift diff with safe reconcile plans.

### Registry page (`/dashboard/docker/registry`)

**Must support (Dockhand parity baseline):**

**Enhancement ideas (v3+):**

### Cross-page non-functional requirements (applies to all Docker pages)

- Real-time aware: each page must support live refresh/stream updates without full reload.
- Failure tolerant: linkage or enrichment failures must not break core runtime operations.
- Safe by default: destructive actions must use explicit confirmation and clear impact messaging.
- Auditable: operator actions should emit timeline/audit-friendly metadata.
- Phase-safe architecture: runtime-first in Phase 1, linked enrichment optional in Phase 2.

### SSE streaming excellence contract (mandatory)

All Docker realtime streams (runtime events, logs, process streams, long-running operation updates) must satisfy this quality bar:

- **Stable delivery semantics**: ordered event emission per stream key with deterministic server sequencing.
- **Resume support**: cursor-based resume (`lastEventId`/explicit cursor input) to recover after disconnects without data gaps.
- **Reconnect behavior**: automatic client reconnect with bounded exponential backoff and transparent state recovery.
- **Heartbeat/keepalive**: periodic heartbeat events to prevent silent dead sockets and to detect stale connections quickly.
- **At-least-once safe consumption**: duplicate-tolerant client reducers and idempotent event application.
- **Filter fidelity**: server-side typed filters (`source`, `action`, `resourceId`, `since`, etc.) must be honored consistently for replay and live paths.
- **Backpressure safety**: bounded buffering and explicit overflow behavior (drop policy + diagnostic event) rather than unbounded memory growth.
- **Error envelope standardization**: typed stream error payloads with machine-readable codes (`upstream_unavailable`, `cursor_invalid`, `stream_timeout`, `auth_forbidden`, ...).
- **Observability**: stream metrics for open connections, reconnect count, replay depth, lag, dropped events, and average delivery latency.
- **Graceful degradation**: if live SSE is unavailable, pages must fall back to polling snapshots with operator-visible degraded-mode indication.

#### SSE acceptance criteria (done definition)

- No event loss across controlled disconnect/reconnect scenarios within retention window.
- Stream consumers recover from transient network failures without full page reload.
- Duplicate events do not produce duplicate side effects in UI state.
- P95 reconnect-to-healthy-stream time stays within defined SLO budget.
- Stream diagnostics are queryable for incident analysis (lag/drops/retries by stream type).

## Execution sequence

1. **Freeze boundary**: treat linked data as optional and prevent it from blocking core pages.
2. **Close Phase 1 API parity**: add missing Docker mutations and operator endpoints to contracts + API module.
3. **Close Phase 1 web parity**: replace placeholder/simulated actions with real mutations + stream feedback.
4. **Harden**: add focused tests for Docker runtime operations and page-level integration behavior.
5. **Start Phase 2**: reintroduce linked deployment/service/project overlays behind optional enrichment adapters.

---

## Phase 1 done definition

- All major Docker operator actions work without `listContainersLinked` context.
- If linkage services fail, container/image/network/volume/stack operations still function.
- No top-level Docker page is blocked by project/service/deployment joins.
- Runtime and mutation state are observable via stream/timeline feedback.
