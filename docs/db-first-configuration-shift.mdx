# DB-First Configuration Shift (Mesh + Runtime)

> **Status**: In progress  
> **Started**: 2026-03-31  
> **Scope**: `v3/apps/api` (`drizzle`, `database`, `local-database`, `mesh`, `@repo/env`)  
> **Tracking**: `T274` in `apps/doc/content/docs/deployment/migration-task-breakdown.mdx`

## Why this exists

This document is the persistent execution context for moving runtime/mesh configuration from environment variables to a DB-first model.

Goal: boot with minimal env, complete configuration in-app, and persist operational settings in the correct data plane:

- **Local SQLite**: node-specific and sensitive config.
- **Global Postgres**: cluster-wide policy and shared runtime behavior.

## Problem statement

Current behavior still relies on many `MESH_*` environment variables for runtime behavior and topology defaults, which creates drift and harder operational mutation.

Target behavior:

1. Node can start with minimal env.
2. Node identity/config live in local DB.
3. Shared mesh policy lives in global DB.
4. Mesh reads config from services backed by DB, not from ad-hoc env reads (except strict bootstrap secrets where unavoidable).

## Source plan (full context capture)

Planned work items:

1. Restructure Drizzle layout into shared custom types + global schema/migrations + local schema/migrations; update exports/import paths.
2. Split DB module responsibilities into `GlobalDatabaseService` and `LocalDatabaseService` wiring by consumer.
3. Extend local SQLite schema for node config + sensitive local overrides (encrypted columns).
4. Extend global Postgres schema for cluster-wide mesh policy.
5. Implement `LocalConfigService` and `GlobalConfigService` (read/update APIs + caching).
6. First boot: generate node ID in local DB, initialize defaults, mesh reads DB.
7. Setup-mode flow to configure through app UI/API.
8. Move mesh topology/logic services to DB-backed config services; trim env usage.
9. Remove non-bootstrap mesh env keys from env schema.
10. Make `db:generate`/`db:push`/`db:migrate` support both global + local flows.
11. Keep docs updated in same change sets.

## Decisions already locked

- Local SQLite stores node-specific config and sensitive values (encrypted columns).
- Global Postgres stores shared cluster mesh policy.
- Node ID is generated and persisted in local DB.
- Setup mode remains the path for first-time configuration.

## Current code baseline (before refactor)

- Drizzle layout:
  - `src/config/drizzle/schema/*` (global)
  - `src/config/drizzle/local-schema/*` (local)
  - `src/config/drizzle/custom-types/*` (shared)
  - `src/config/drizzle/migrations/*` (global migrations)
- Config files:
  - `drizzle.config.ts` -> `schema/index.ts`, `migrations`
  - `drizzle.config.local.ts` -> `local-schema/index.ts`, `local-migrations` (directory not yet materialized)
- DB modules:
  - `DatabaseModule` builds Postgres connection and already can resolve `DATABASE_URL` from local `node_config` fallback.
  - `LocalDatabaseModule` initializes local SQLite and creates local tables if missing.
