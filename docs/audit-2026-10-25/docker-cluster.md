# Audit: Docker / Swarm / Cluster / Nodes / Fleet / Runtime

Scope: `apps/api/src/modules/{docker,cluster,fleet}`, `packages/nest/{docker,swarm,nodes,supervisor-core,lifecycle}`, `apps/api-services/services/{fleet,runtime}`, `packages/contracts/{fleet,runtime}`, web `dashboard/{docker,cluster,nodes}`, `docs/swarm-orchestration`, `docs/FLEET-CENTRIC-FRONTEND-REWRITE.md`.
All paths are relative to `/home/sebille/Bureau/projects/tests/deployer/v3`. Every claim below was read in source; the only thing executed was `packages/nest/swarm` tests (8 files / 64 tests, green).

Status legend: REAL = implemented and wired end to end. PARTIAL = works but with a material hole. STUB = fake, logs, derived or UI-only. MISSING = not there.

## 0. Structural fact that affects everything

The code exists twice. `apps/api/src/modules/{docker,cluster,fleet}` is the monolith; `apps/api-services/services/runtime` (docker + deployment) and `apps/api-services/services/fleet` (cluster + fleet + providers) are near-verbatim copies. `diff` shows the `cluster`/`fleet` copies differ only in import paths (`@deployer/nest-schema/global` vs `.../global/fleet/cluster`). Every bug below therefore exists in both copies, and any fix has to land twice until `apps/api` is deleted (see `docs/API-CUTOVER-STATUS.md`). The BFF delegation file (`apps/api-services/bff/src/modules/delegation/generated/nodes.delegation.ts` header) claims "the service enforces role gates on the procedures that need them". For docker/cluster/fleet that claim is false (section 3, item 1).

## 2. What works end to end

- Single-node and multi-node bootstrap: swarm init bound to the WireGuard mesh address, token-based join via the mesh join-grant (anonymous grant redemption -> role decision -> token delivery -> join -> wait for active), including the manager-count parity rule and auto-leave of a lone self-founded cluster. Backed by passing tests.
- Platform services as swarm services with supervised convergence, retry of degraded supervisors and a health sweep.
- Docker observability: container/image/network/volume listing, inspect, logs, processes, runtime event + activity streams, the entity store, and mesh fan-out so a single dashboard shows containers from every node.
- Container operations on the node you are connected to (and logs/files/terminal/inspect across the mesh): start/stop/restart/pause/kill/remove, file browser, interactive terminal.
- Image security scanning pipeline with streamed progress and persisted results.
- Live cluster views: snapshot, nodes, services/tasks, per-node swarm tasks, swarm event feed.
- Writing ingress / platform-role labels to the swarm node (the write is real; only the platform-role consequence is missing).
- Swarm deploy path (opt-in runner): creates overlay networks, attaches to the platform overlay so Traefik can reach the service, create-or-update with start-first + rollback, task-state health gate, Traefik route verification.

## 3. Broken or risky

Security and correctness first.

1. No authorization beyond "logged in" on any docker/cluster/fleet procedure. `requirePlatformRole` exists and is used in deployment and reachability controllers, but `docker.controller.ts`, `cluster.controller.ts`, `fleet.controller.ts` use only `requireAuth()`. Consequences for any authenticated account including Viewer: shell and file write/delete in any container (platform ones too); kill/remove any container; read raw container env (`docker.repository.ts:1085` returns `Config.Env` unredacted; the redaction at `:598-606` applies only to service entities); change swarm participation, node roles and ingress labels; set node capacity; create/delete allocations; approve own admission request. There is also no tenancy check tying a container to a project.
2. Swarm join tokens leak to every authenticated user: `cluster.getSnapshot`/`streamSnapshot` return `joinTokens {worker, manager}` (`swarm-cluster.service.ts:176-178`) and `cluster.getSwarmConfig` returns them in the view (`swarm-participation.service.ts:434`). A manager token plus reachable mesh/control-plane address is a full takeover of the cluster. Tokens are also stored in plaintext in local SQLite (`cluster-node.repository.ts` `joinToken*` columns) and in `node_config.swarmConfig`.
3. Label injection / override in the swarm runner (`swarm-runtime-runner.service.ts:114,429-441`). Same weakness exists in the plain docker runner (`sanitizeExecutorLabels`).
4. Election is not a distributed election: per-node SQLite CAS, constant fake metrics, term reset by `persistSnapshot`, hardcoded `healthy` on the SSE (see 1.2). Do not rely on "controlling master" for any decision; the UI presents it as authoritative.
5. Node health is wrong: crashed nodes stay "active" in inventory (`state:"active"` forced on upsert); `cluster_nodes.status/healthy` forced active by `enrollLocalNode`; fleet metrics are mislabelled link-quality numbers, one DB row per heartbeat with duplicated server rows and no retention.
6. UI says things happen that do not: create container ("created" toast), approve admission "grants an allocation", platform role "control/worker" removes workloads / changes managers, pull image progress.
7. Remote-container actions (start/stop/kill/remove) fail on peers while listing/terminal work. Operators will see a container and be unable to act on it.
8. Data loss on redeploy: per-deployment volume name; node-local volumes with no placement pinning; no volume list/cleanup UI to even notice orphans.
9. Multi-node image distribution is unsolved: images are built locally (`DockerService.buildImage`), no registry push, no private-registry auth, `deployer-scanner-runner:latest` is locally built. A service scheduled on a second node cannot start.
10. No capacity safety: reservations are empty, allocations unenforced, SW-033 open; user workloads can starve Raft managers (the doc's own risk).
11. Silent error handling: `participation.applyConfig` swallows converge failures (`:~404`), `persistSnapshot` swallows, `SwarmBootstrapService.converge` never throws, `removeImage` swallows, `listAllSwarmTasks().catch(() => [])` in `swarm-fleet.service.ts:41` makes services show 0 running tasks on error, `refreshAllState` swallows.
12. Docs drift: `docs/swarm-orchestration/README.md` still says "Design finalized, implementation pending"; IMPLEMENTATION_TODO marks SW-045/054/055/056/061/062/063/072/073/033/015 open; term-in-shared-PG is documented but implemented as local SQLite; `swarm-orchestration` doc says secrets should move to swarm secrets (SW-073) - not done.
13. Duplication: monolith + services copies of docker/cluster/fleet (~20k lines) will drift.
14. Minor: `docker.service.ts` nginx fallback assigns `options.image` (lowercase) so the fallback image is never used; `planQuorum(snapshot.nodeCount, snapshot.managerCount)` in the leadership service passes the manager count as `quorumMax`, so the "plan" is meaningless; `cluster.listNodes` default `includeDown` hides down nodes but down detection is the broken one in item 5.

## 4. Required for production (ordered)

1. Authorization pass (blocking). Introduce one shared role policy for these three modules: read = any member; container lifecycle/exec/files, swarm config, node labels, capacity, allocations, admission resolution = admin/operator (reuse `requirePlatformRole`). Add project-scoped checks for container exec/files/actions (container -> project label -> membership). Protect platform containers/services (deny kill/remove/exec unless superAdmin). Record `reviewedByUserId`. Do in both the monolith and the services copies (or finish the cutover first).
2. Remove join tokens from `getSnapshot`, `streamSnapshot` and `getSwarmConfig` responses; expose them only through an explicit admin "issue join token / grant" procedure (the join-grant flow already exists); encrypt/avoid persisting tokens at rest and rotate them after use.
3. Make node status truthful: derive `down/ready/draining` from `Status.State` and `Spec.Availability` in `toEngineNodeRow`; stop forcing `active/healthy` in `enrollLocalNode`; fix `cluster_node_metrics` (unique `node_id` upsert or latest-row subquery + retention job); replace the mesh-derived pseudo CPU/memory with real node stats (engine `info` NCPU/MemTotal + cAdvisor-style stats, or the mesh agent) and rename the fields honestly.
4. Fix election honesty: either (a) delete the custom election and use the swarm raft leader (the snapshot already does) and remove the "elected master" UI claims, or (b) store term/CAS in the shared PG, supply a real metrics provider (mesh RTT), stop `persistSnapshot` from overwriting term, wire the event sink, and make the SSE use the same source as `getMaster`.
5. Fix the UI lies: wire or remove "Create container" (and show an honest pull path), remove "Approving grants an allocation" or implement it, and make `platformRole` real (see 6) or relabel it as advisory. Delete the dead cluster components or switch the page to `ClusterNodesTable` (it has the quorum confirmation).
6. Make roles enforceable: add scheduling constraints on `deployer.node.role` for control-only nodes, and real promote/demote/drain/remove-node procedures (`docker node update --role/--availability`, `node rm`) with quorum pre-checks and a drain-before-demote safety. Expose them in the nodes UI with confirmation.
7. Image distribution for multi-node: add a registry (platform-run or external) with credentials stored encrypted; push builds; pass `registryAuth` to pulls and as `X-Registry-Auth`/`--with-registry-auth` for service create/update; add registry CRUD contract + UI; build/publish the scanner runner image like any other.
8. Persistence and storage correctness: stable per-service volume name (not per-deployment), node pinning or a shared-storage driver for volumes, volume/network management procedures, and orphan detection.
9. Replace hardcoded `replicas: 1`: add service replicas/placement/resource fields to the service config, call `scaleService`/`rollbackService` from real endpoints, set reservations, and enforce fleet allocations in deployment admission (or delete the allocation model).
10. Sanitise executor labels (allow-list `deployer.placement` and user labels under a reserved prefix; never let users set `traefik.*` or `deployer.managed*`).
11. Add remote-node action routing for container lifecycle over the mesh, mirroring the existing logs/files/terminal handlers.
12. Cleanup tooling: image/volume/network/builder prune (dry-run + scheduled retention), because nothing frees disk today.
13. Decide the monolith/services question and delete one copy; make the swarm runner the default runner when a swarm is active, or document why not.
14. Close the open doc/TODO items (SW-033, 045, 054, 055, 056, 072, 073) or prune them; update `docs/swarm-orchestration/README.md` status.
15. Observability and error surfacing: stop swallowing converge errors in `applyConfig` (return the failure to the UI), surface supervisor degraded state on the cluster page, and add multi-node DinD e2e (SW-056) for join, drain, node-loss.

## 5. Recommended enhancements

- Node detail: show real CPU/memory/disk and per-node container list (tasks) with the live engine stream rather than "local only" images/networks/volumes; add `docker system df`-style disk usage.
- Cluster page: show quorum health (reachable managers vs required), per-node `Status.State`, last-seen from the swarm itself, and a node timeline from the existing activity store.
- Replace the shell-escaped exec approach for file edits with `putArchive`/`getArchive` (binary-safe, no shell dependency in distroless images); add upload/download.
- Terminal: audit-log every session (who, container, duration); optional per-role allow-list; idle timeout.
- Image scan: per-image SBOM, policy gate that blocks deploy on critical findings (the scan already runs), rescan schedule; use a registry digest for dedupe across nodes.
- Cluster events: use `notifyMutation()` after label/config writes; unify the master/nodes streams with the REST shapes (fix `readNodes()` omitted fields).
- Contract hygiene: drop the type-only registries/stacks modules or finish them; share one `docker`/`cluster` contract package between BFF and services.
- Unit tests: controllers have no authorization tests; add negative tests per role (Viewer must get FORBIDDEN).

## 6. Recommended new features

- Node lifecycle workflows: "Add node" wizard in the dashboard (issue join grant, show the join command/QR, wait for active), "Drain & remove node", "Promote to manager", "Quorum repair" (SW-054).
- Docker secrets and configs management (UI + API) with mounting support in `toDockerServiceSpec` (`Secrets`/`Configs`), replacing plaintext env for sensitive values; rotation.
- Private registry manager and per-project pull credentials; registry mirror/cache per node.
- Service operations UI: scale, rolling restart, rollback, pause/resume, update-config (parallelism/delay/order), per-service placement editor (region/zone/tenant labels, max replicas per node, spread).
- Automatic cleanup policies: per-node prune schedules, disk-pressure alerts, image GC by age/usage.
- Drift reconciliation that actually acts: wire `DriftReconciliationService` (or replace) to a scheduler comparing desired deployments to `docker service ls` and either alert or redeploy.
- Capacity-aware scheduling: reservations from allocations, admission control before deploy, per-project quotas, node cordon on disk/memory pressure.
- Node-level metrics history (Prometheus-style) and alerting for node down, task flapping, quorum risk.
- Multi-region spread presets and "dedicated node for project" workflows that set the labels the placement builder already expects.
